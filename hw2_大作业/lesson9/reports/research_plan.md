# HW2 研究方案：零售银行客户分群与客户价值识别

> 数据：`data/mall_customers_sim.csv`（课程提供的**模拟客户数据**，非真实银行业务数据）
> 目标读者：银行零售业务部经理
> 本文是研究方案，所有结果以实际运行输出为准，方案中不预设结论。

## 一、业务问题与研究目标

### 1.1 业务问题

零售客户在收入、资产、年龄、产品持有上差异很大，用同一套营销资源覆盖全部客户，成本高且转化低。
业务部门需要回答三个问题：

1. 现有客户可以分成哪几类？各类的规模有多大？
2. 每类客户的价值与需求差异体现在哪些特征上？
3. 针对不同客群，资源应如何差异化配置？

### 1.2 研究目标

1. 用无监督学习对客户做分群，不预设标签；
2. 对比 KMeans 与 DBSCAN 在客户数据上的表现，说明各自适用性；
3. 输出可解释的客户画像与业务建议；
4. 全程保留可复现的代码、数据与评估指标。

### 1.3 明确的边界

- 数据为模拟数据，结论只用于方法演示，不能表述为真实银行经营结论；
- `customer_id` 仅作标识，绝不进入模型；
- 分群结果需要业务校验，不能只凭算法输出直接执行。

## 二、数据初检与预处理

### 2.1 初检项

| 检查项 | 方法 | 处理原则 |
|---|---|---|
| 数据规模 | 行列数 | 记录样本量 |
| 缺失值 | 逐列统计 | 缺失比例低则删除该行，否则填补（需说明） |
| 重复值 | 全行去重 + customer_id 查重 | 重复行删除；编号重复需核查 |
| 异常值 | IQR 1.5 倍法则 + 业务合理范围（如年龄 18~100、余额非负） | 先标记、不盲目删除，结合业务判断 |
| 数据类型 | dtypes | 数值/分类分开处理 |

### 2.2 特征与字段处理

- **进入模型的数值特征**：`age`、`income`、`balance`、`product_count`；
- **排除字段**：
  - `customer_id`：唯一标识，无业务含义，进入模型会引入噪声与泄漏；
  - `gender`、`city`：分类字段，KMeans/DBSCAN 基于欧氏距离，不能直接使用。
    若后续需要使用，单独说明编码方式（如 one-hot），并评估维度膨胀与距离失真问题；
- **标准化**：距离类模型必须使用 `StandardScaler`，消除"元 vs 万元"等量纲差异；
  标准化只改变度量衡，不改变客户原始数值。

### 2.3 输出物

- `generated/01_preprocessing.py`、`generated/cleaned_data.csv`、`generated/preprocessing_report.md`
- 报告需给出预处理前后的统计对照（均值、标准差、缺失、重复、异常值数量）。

## 三、特征选择及理由

| 特征 | 业务含义 | 选择理由 |
|---|---|---|
| `age` | 人生阶段 | 影响风险偏好、产品需求（首卡、房贷、养老） |
| `income` | 收入能力 | 决定可支配资金与授信空间 |
| `balance` | 账户资产 | 反映客户在本行的资金沉淀与贡献 |
| `product_count` | 产品持有广度 | 反映关系深度与交叉销售空间 |

不选 `gender`、`city` 的原因：一是分类变量不适合欧氏距离；二是避免把敏感属性直接用于差异化定价，
存在合规风险；如确需分析，应作为分群后的描述维度，而不是聚类输入。

## 四、模型一：KMeans 客户聚类

- 输入：预处理后的标准化四特征；
- 参数：`KMeans(n_clusters=K, random_state=42, n_init=10)`；
- 选 K：K 从 2 到 9，逐一计算 `inertia_` 与 `silhouette_score`，
  肘部法看 SSE 拐点，轮廓系数看簇内紧密度与簇间分离度；
- 确定 K 时同时考虑：指标表现 + 业务可解释性 + 各簇规模是否过小；
- 输出：各簇人数与占比、四特征均值、二维可视化（income × balance，标注簇中心）；
- 产物：`generated/02_kmeans.py`、`kmeans_results.csv`、`kmeans_report.md`、`outputs/01_kmeans.png`。

## 五、模型二：DBSCAN 密度聚类

- 输入：与 KMeans 完全相同的标准化数据；
- 参数：`eps` 与 `min_samples` 网格尝试，记录每种组合的簇数、噪声数、噪声占比与轮廓系数；
- 选择规则：优先簇数在业务可解释范围内（如 2~6）、噪声占比可控，再看轮廓系数；
- 输出：簇数、各簇人数、噪声点数量、可视化；
- 产物：`generated/03_dbscan.py`、`dbscan_results.csv`、`dbscan_report.md`、`outputs/02_dbscan.png`。

## 六、模型评估与结果比较

1. **轮廓系数**：KMeans 用最终 K 计算；DBSCAN 在非噪声点上计算（需说明样本范围不同）；
2. **簇数量**：KMeans 固定 K，DBSCAN 自动发现；
3. **噪声点**：DBSCAN 独有，需报告数量与占比；
4. **簇规模**：比较最大/最小簇、是否出现极小簇；
5. **一致性**：用 ARI 比较两种划分的重合程度；
6. **结论原则**：不以单一指标定优劣，结合业务可解释性、覆盖率、稳定性综合判断。

产物：`generated/04_model_evaluation.py`、`model_comparison.csv`、`model_comparison.md`、`outputs/03_model_comparison.png`。

## 七、客户画像分析

- 基于最终选定模型的分群结果，`groupby` 统计每簇：人数、占比、平均年龄、收入、余额、产品数；
- 命名规则：依据各簇均值相对全局均值的高低自动生成中文业务名称，不用簇编号代替结论；
- 每个客群说明：特征、价值水平、潜在需求、风险点；
- 产物：`generated/05_business_analysis.py`、`customer_segments.csv`、`business_analysis.md`、`outputs/04_customer_segments.png`。

## 八、业务结论与建议

- 按客群给出差异化策略：高价值维护、成长型培育、稳健型留存、低价值低成本触达；
- 每条建议必须对应实际统计特征，不写无数据支撑的口号；
- 明确说明：模拟数据结论不构成真实经营建议，落地前需真实数据验证。

## 九、局限性与改进方向

1. **模拟数据**：样本仅 300 条，分布为人工设定，不能外推到真实客户；
2. **特征有限**：缺少交易行为、渠道偏好、风险等级、时间序列信息；
3. **KMeans 假设**：簇为凸球形、对异常值与初始中心敏感；
4. **DBSCAN 参数敏感**：eps/min_samples 依赖经验与网格搜索，高维下密度定义退化；
5. **评估无真值**：无监督指标只能衡量几何结构，不能证明业务有效性；
6. **改进方向**：引入 RFM/交易特征、使用 GMM 或层次聚类、做稳定性与时间外验证、
   用真实业务指标（AUM、留存率）做后验评估。
